# Protocol

This document fixes the problem, the workload grid, the metrics and the
measurement rules **before** any result is collected. Changes to it after
results exist must be made in a separate commit that explains why.

## 1. Problem

Given pairs of byte strings `(a, b)`, compute the **exact unit-cost Levenshtein
distance**: the minimum number of single-character insertions, deletions and
substitutions turning `a` into `b`.

- Score only. No alignment path / CIGAR.
- Exact. Not threshold-bounded ("is it ≤ k?") and not approximate.
- Bytes, not Unicode code points. (UTF-8 is out of scope for now.)

Two workload shapes are measured separately:

| Shape | Input | Output | Real-world analogue |
|---|---|---|---|
| **pairs** | N independent pairs `(a_i, b_i)` | N distances | read-vs-reference checks, dedup of candidate pairs |
| **cross** | Q queries × C candidates | Q×C matrix | fuzzy search: one query against a dictionary (`cdist`) |

## 2. Workload grid

| Axis | Values |
|---|---|
| length of `a` (L) | 16, 32, 64, 128, 256 |
| error rate (edits / L) | 0.01, 0.05, 0.20, 0.50 |
| alphabet | `dna` (ACGT), `bytes` (62 alphanumerics, uniform), `text` (a-z + space, English letter frequencies) |

Pairs are generated by `bench/datagen.py`: `a` is drawn from the alphabet, `b`
is `a` with `round(error_rate * L)` random edits (substitution / insertion /
deletion, equally likely). Generation is deterministic given the seed. Note the
true distance can be *below* the number of applied edits (edits can cancel);
ground truth is always computed, never assumed.

The `--quick` grid is L ∈ {16, 64, 256}, error ∈ {0.05, 0.20}, alphabet `bytes`.

## 3. Metrics

- **Primary:** pairs per second (cross shape: matrix cells per second), reported
  separately for **1 thread** and **all threads**.
- **Secondary:** DP cell updates per second (`L_a × L_b` per pair; the standard
  unit in the alignment literature), and ns per pair.
- Every row reports the median and inter-quartile range over repetitions.
- **End-to-end** pairs per second (`e2e_pairs_per_s`) additionally includes the
  contender's conversion from Python lists (`prep_s`, median of 3). Libraries
  that read Python strings directly pay that cost inside the timed call, so
  kernel-only numbers favour contenders with a separate conversion step; both
  are reported and claims must state which one they use.

## 4. Correctness rules

1. Ground truth is the textbook O(n·m) DP (`reference.dp_distance`).
2. A second, independent implementation (`reference.myers_distance`,
   bit-parallel over Python integers) must agree with it on all tests.
3. Every library or kernel under test passes a **correctness gate** on each
   bucket before it is timed: its outputs on a sample are compared with ground
   truth. A single mismatch excludes it from that bucket and is reported.
4. Property tests: `d(a,a)=0`, symmetry, triangle inequality,
   `|len a − len b| ≤ d ≤ max(len a, len b)`, empty strings, and the bit-vector
   word boundaries 63/64/65 and 127/128/129.

## 5. Fair-baseline rules

- Latest released versions, recorded automatically.
- Each library through its best-suited public API for the shape (batch API if it
  has one), with the same thread count as every other contender.
- When an API forces extra work (e.g. computing a full matrix to obtain pairs),
  that variant is labeled as such, not silently compared.
- Maintainers' recommended settings are adopted when known; we ask them before
  claiming any win.

## 6. Measurement rules

- One warm-up run, then `--reps` (default 5) timed runs; report median and IQR.
- Results are consumed (summed into a checksum) so no work can be optimized away.
- Timed region excludes data generation and string-container construction;
  each library's conversion cost is reported once, separately, where it exists.
- Machine on mains power, other applications closed; environment JSON
  (CPU, cores, OS, Python, library versions, git commit) saved with every CSV.
- Raw CSVs are committed to `results/` and never edited by hand.

## 7. Reporting rules

- Report every bucket, including ones where we lose.
- Speedups are quoted per bucket against the **best** baseline in that bucket,
  never against a cherry-picked one.
- Ablations: each optimization is switched off individually to attribute gains.
